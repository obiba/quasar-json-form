# Internationalization

<p class="doc-lead">Every title, description, option label, hint and message of a form goes through vue-i18n <code>t()</code>.</p>

Strings can be i18n keys or literals: an unknown key is displayed as-is. Set `missingWarn: false`
on the i18n instance to silence the warnings for literal strings. Switch the language in the header
to see the keys of this example resolve.

## Self-contained forms

A form designed outside of the application, by a content manager, cannot rely on the application
bundles: the `translations` prop of `QJsonForm` embeds its own messages, keyed by language, and
the `locale` prop selects the language of the form independently of the vue-i18n locale.

```js
const translations = {
  en: { 'name.title': 'Name', role: { title: 'Role' } },
  fr: { 'name.title': 'Nom', role: { title: 'Rôle' } },
}
```

```html
<QJsonForm v-model="data" :schema="schema" :uischema="uischema" :translations="translations" locale="fr" />
```

Keys can be flat (`name.title`) or nested (`{ name: { title } }`). Every key of the schema and UI
schema is looked up in the form translations first, for the form locale (`fr-CA` also tries
`fr`), then for the vue-i18n fallback locale, and only then in the application messages and in the
built-in defaults. Validation messages follow the same rules, so a form can carry its own
`name.error.minLength` or `error.required`. The locale also selects the language initially
displayed by the [localized string](#/controls/localized-string) controls. Switch the language
of the example with the toggle in its header: the site language does not change.

Both can also be provided at the application level, under the `I18N_KEY` (`jsonforms-i18n`)
injection key, as a `{ locale, translations }` object or a ref of one; the props of a form take
precedence.

## Validation messages

Error messages are looked up under the [JSON Forms i18n keys](https://jsonforms.io/docs/i18n):
`<path>.error.<keyword>` for a specific control, then `error.<keyword>` (`error.required`,
`error.minLength`, `error.pattern`...) with the AJV error params available for interpolation
(`{limit}`, `{pattern}`, `{format}`...), then `error.default`. Keys missing from the application
bundles fall back to the library defaults, in english and french, exported as `messages`:

```js
import { messages } from '@obiba/quasar-ui-json-form'

createI18n({
  legacy: false,
  locale: 'en',
  messages: { en: { ...messages.en, ...appEn }, fr: { ...messages.fr, ...appFr } },
})
```

The built-in keys are `error.*` (one per AJV keyword, plus `wordLimit`, `wordMin`, `wordMax`,
`dateRange`, `dateMin`, `dateMax`, `dateInvalid`), `words`, `localized.completed`, `markdown.*`
(toolbar titles), `files.*` (upload, empty, missing, minItems, maxItems, uploadFailed, remove,
download) and `radioMatrix.allItemsSelected`.

## Renderer messages

A renderer-level check (word limit, date bounds, localized string completed, file count, radio
matrix) reads its message from `options.validationMessage.<name>` on the control when defined,
translated with `t()`. A single string applies to every check of the control, and in a map
`default` is the fallback of the named messages. See [Validation](#/start/validation).

## Application keys

A few labels are read from the application bundles, without built-in default: `add-item`,
`confirm-remove-item`, `cancel` and `remove` for [lists](#/controls/list), `continue` and `back`
for the [stepper](#/layouts/stepper), and `noValue` for a [computed](#/controls/computed)
control.

## Localized strings

[Localized string](#/controls/localized-string) controls hold one value per language. The
languages come from `options.languages` on the control, then `config.languages`, then the
`languages` prop of `QJsonForm` (or a `jsonforms-languages` provide at the application level, a
plain value or a ref), and default to `['en']`. The language initially displayed is the form
locale (the `locale` prop, else the vue-i18n locale) when it is one of them.

## Without vue-i18n

The forms still render: strings are displayed untranslated and the validation messages come from
the built-in english defaults. A warning is logged once.
